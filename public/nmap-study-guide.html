Set up a reproducible lab session

These are command templates, not executed results. Use your assigned training target. The examples assume Linux; raw-packet scans normally need sudo. Save each run under a fresh stem rather than overwriting evidence. 

# Run in your Linux training VM. Replace the placeholders first.

mkdir -p ~/htb/nmap/{scope,scans,reports,notes}
cd ~/htb/nmap
printf '%s\n' "$TARGET" > scope/targets.txt
nmap --version

01. Enumeration

Enumeration turns observations into a model of the target. Begin with a question, select a probe that can answer it, record the response and decide what remains unknown. A list of open ports is a starting point, not a finished assessment. Keep facts, guesses and next tests separate. The workflow diagram shows why useful enumeration is iterative.

02. Introduction to Nmap

Nmap combines host discovery, port scanning, service probes, OS fingerprinting and scripts. These are distinct phases with different network effects. Choose scan type, options and target explicitly. On Linux, raw-packet scans such as SYN scanning normally need elevated privileges; an unprivileged TCP connect scan uses the operating system’s connection mechanism. The default scan covers common TCP ports, not every TCP and UDP port.

Practice checkpoint: Explain the purpose of each flag before running a command, and record your installed version. 

nmap --version
nmap --help
# A basic scan of the assigned host, saving a baseline:
nmap -n --reason -oA scans/initial "$TARGET"

03. Host Discovery

Host discovery asks which addresses respond to selected probes. No answer can reflect filtering, packet loss or an unavailable system. On a local Ethernet network, privileged Nmap normally uses ARP for IPv4 or Neighbor Discovery for IPv6; an ICMP option alone does not remove that behavior. Use -sn for discovery without a port scan. Use -sL -n to inspect the target list without probing hosts or performing reverse DNS. -Pn skips discovery and assumes targets should be scanned; it does not prove that a host is online.

Practice checkpoint: Compare target-list expansion, discovery responses and a targeted -Pn follow-up without mixing their conclusions. 

nmap -sL -n -iL scope/targets.txt
sudo nmap -sn -n --reason -iL scope/targets.txt -oA scans/discovery
# Isolate ICMP echo behavior rather than substituting ARP discovery:
sudo nmap -sn -n -PE --disable-arp-ping --packet-trace "$TARGET"
# A focused follow-up when discovery may be filtered:
sudo nmap -Pn -n -p "$PORTS" --reason -oA scans/no-discovery "$TARGET"

04. Host and Port Scanning

Keep TCP and UDP results separate. In a SYN scan, SYN/ACK supports open and RST supports closed; filtering errors or repeated silence can produce filtered. A connect scan completes a TCP connection. UDP often gives no response, so open|filtered is not proof of an open UDP service. Use --reason and narrowly scoped packet traces to connect a reported state to the evidence that produced it. A full TCP port range does not include a full UDP scan.

Practice checkpoint: Explain one result using the probe, reply, protocol and scan type. Use the state table and response diagram below. 

# Privileged SYN scan; -p- covers TCP ports 1 through 65535 here.
sudo nmap -sS -p- -n --reason -oA scans/all-tcp "$TARGET"
# Explicit connect scan for comparison on selected ports:
nmap -sT -p "$PORTS" -n --reason -oA scans/connect "$TARGET"
# Targeted UDP follow-up: change these example ports to match the task.
sudo nmap -sU -sV -p 53,161 -n --reason -oA scans/udp "$TARGET"
# Inspect one TCP port; packet traces can be large on wider scans.
sudo nmap -sS -Pn -n -p 80 --reason --packet-trace "$TARGET"
Interpret port states in the context of the scan type
State Meaning
open A service accepted the relevant probe.
closed The port is reachable, with no listening service indicated.
filtered Filtering prevents a clear open/closed decision.
unfiltered An ACK probe received a response; open versus closed remains unknown.
open|filtered The scan cannot distinguish an open service from filtering.
closed|filtered The idle-scan result cannot distinguish closed from filtered.

05. Saving the Results

Preserve raw results as you work. -oN produces readable normal output, -oX produces XML for structured processing, and -oG produces the older grepable format. -oA writes all three with one stem. Keep command, target, time and network position alongside each result. Prefer XML for reliable parsing rather than brittle text extraction. HTML reports are transformations of XML, not a direct Nmap output mode. The credited report screenshot is a historical example, not your result.

Practice checkpoint: Create a fresh output stem, locate all three files and produce a readable HTML report from the XML. 

sudo nmap -sV -p "$PORTS" -n -oA scans/services "$TARGET"
ls -l scans/services.nmap scans/services.xml scans/services.gnmap
# xsltproc must be installed; adjust the stylesheet path for your system.
xsltproc -o reports/services.html /usr/share/nmap/nmap.xsl scans/services.xml
# Some systems also support the XML document’s embedded stylesheet:
# xsltproc scans/services.xml -o reports/services.html

06. Service Enumeration

A port number suggests a conventional service; it does not establish the actual application. -sV sends probes and matches responses to service signatures. Start with ports already discovered, then investigate uncertain services. --version-light uses a smaller probe set. A banner can omit versions or be misleading; corroborate it with protocol behavior. OS guesses and service versions are hypotheses, not proof that a vulnerability is exploitable. Progress reporting does not itself speed up a scan.

Practice checkpoint: For one port, distinguish the port-based label, probe-derived product evidence and a manually observed response. 

sudo nmap -sV --version-light -p "$PORTS" -n -oA scans/versions-light "$TARGET"
sudo nmap -sV -p "$PORTS" -n --stats-every 10s -oA scans/versions "$TARGET"
# Optional OS fingerprinting when the exercise calls for it:
# sudo nmap -O --osscan-limit -n -oA scans/os "$TARGET"
# Example banner inspection only when the assigned host exposes SMTP:
nc -nv "$TARGET" 25
# For a discovered HTTP service:
curl -I "http://$TARGET/"

07. Nmap Scripting Engine

NSE scripts perform service-specific checks. -sC selects the default set; --script can select exact names or categories. Read script help and prerequisites first. Category labels are not a guarantee that a script fits your scope, and a vulnerability-script finding needs validation. Broad categories can include intrusive behavior or external lookups. -A combines OS detection, version detection, default scripts and traceroute; it is not simply a faster scan.

Practice checkpoint: Choose one named script that answers a specific question and explain why its prerequisites are satisfied. 

# Local help; inspect what the named scripts do.
nmap --script-help http-title,http-headers,banner
# Only on the relevant web ports discovered in your authorized lab:
nmap -sV -p 80,443 --script http-title,http-headers -n -oA scans/http-scripts "$TARGET"

08. Performance

Tuning changes the balance between time, traffic and completeness. Keep target, ports and network position constant while changing one setting. Tight response timeouts or fewer retries can hide slow responses; high minimum rates can force traffic faster than a path handles well. -T3 is the default timing template, while -T4 assumes a reasonably fast, reliable path. Keep both result sets and investigate differences rather than treating a faster run as automatically better.

Practice checkpoint: Compare elapsed time and discovered states between a baseline and one controlled timing change. 

sudo nmap -sS -T3 -p "$PORTS" -n -oA scans/timing-baseline "$TARGET"
sudo nmap -sS -T4 -p "$PORTS" -n -oA scans/timing-t4 "$TARGET"
# ndiff is an optional Nmap-suite tool. Review changes in saved XML.
ndiff scans/timing-baseline.xml scans/timing-t4.xml
# Also retain the original Nmap output and elapsed-time summaries.

--max-retries limits retransmissions; RTT options adjust response waiting; --min-rate requests a minimum probe rate while --max-rate caps the probe rate. Treat reduced coverage as a possible accuracy loss and retest conservatively.

09. Firewall and IDS/IPS Evasion

Filtering, alerting and active prevention are different mechanisms. Compare a small SYN scan with an ACK scan to investigate packet handling. ACK scanning can classify filtered versus unfiltered, but does not identify open ports. A source-port change tests a particular policy assumption; using port 53 does not turn TCP traffic into DNS. Raw-probe options may not apply to service detection or NSE connections. No option guarantees invisibility or a bypass. Decoys, source spoofing and fragmentation are controlled-lab experiments, not universal fixes.

Practice checkpoint: Change one probe property and describe the observed policy behavior, including what the evidence cannot establish. 

sudo nmap -sS -Pn -n -p "$PORTS" --reason -oA scans/syn-policy "$TARGET"
sudo nmap -sA -Pn -n -p "$PORTS" --reason -oA scans/ack-policy "$TARGET"
# One lab port only; first compare against the baseline without this flag.
export LAB_PORT='REPLACE_WITH_ONE_ASSIGNED_LAB_PORT'
sudo nmap -sS -Pn -n -p "$LAB_PORT" --source-port 53 --reason -oA scans/source-port-test "$TARGET"

-n disables name resolution. --dns-servers selects DNS resolvers; it does not proxy the port scan. Decoy addresses and spoofed sources require an appropriate controlled topology and reply path. Fragmented raw IPv4 probes can be reassembled or normalized by the path; they do not fragment every Nmap application connection.

12. Firewall and IDS/IPS Evasion - Hard Lab

The final lab asks you to adapt to another defensive change. Re-enumerate rather than reusing a previous service label or answer. Build a hypothesis about the specific behavior that differs, test it narrowly and validate any recovered service information with an appropriate protocol interaction. Preserve the successful command and the failed alternatives so you can explain why the result changed. Finish with evidence and remediation, not only an answer submission.
